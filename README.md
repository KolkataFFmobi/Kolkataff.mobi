# kolkataff.mobi — Kolkata FF (Kolkata Fatafat) Results Archive

**Live site: [kolkataff.mobi](https://kolkataff.mobi/)**

A dependency free static site generator that publishes **Kolkata FF** results — every declared Patti and Single, checked against multiple public sources before it goes live.

Built with Node.js standard library only. No frameworks, no CMS, no database, no third party JavaScript beyond a single analytics tag. The whole site is generated by one script and deploys as static files.

---

## What Kolkata FF is

**Kolkata FF** — also written **Kolkata Fatafat**, **কলকাতা ফটাফট**, *Kolkata Fatafati*, *Kolkata Fotafot*, *Calcutta Fatafat*, or *KolkataFatafat*, and commonly abbreviated **KFF** — is a fast cycle, number based lottery style game played in **Kolkata, West Bengal, India** ([Wikidata Q1348](https://www.wikidata.org/wiki/Q1348) / [Q1356](https://www.wikidata.org/wiki/Q1356)). It descends from the Satta Matka tradition.

The game's structure, stated as plain facts:

| Subject | Relationship | Object |
| --- | --- | --- |
| Kolkata Fatafat | is played in | Kolkata, West Bengal, India |
| Kolkata Fatafat | derives from | the Satta Matka tradition |
| A day (Mon–Sat) | contains | 8 rounds, called *bazi* |
| A Sunday | contains | 4 bazi |
| Each bazi | produces | one Patti and one Single |
| A Patti | is | a three digit number from the fixed 220 Patti set |
| A Single | is | the last digit of the Patti's digit sum |

**The derivation rule, worked:** Patti `368` → 3 + 6 + 8 = 17 → last digit **7** → Single is **7**.

That rule never varies, which makes every published pair independently checkable — and it is exactly what this codebase validates on ingest.

## Correctness is enforced, not assumed

Every build runs 22 assertions and refuses to produce output if any fail. The ones that matter most:

- **Four way sync** — the homepage's visible timestamp, its JSON-LD `dateModified`, the sitemap `lastmod`, and the file mtime all derive from one variable and must match exactly.
- **Digit sum validation** — a Patti and Single pair that breaks the derivation rule cannot enter the dataset.
- **220 Patti membership** — every declared Patti must belong to the computed canonical set.
- **Content policy** — a word list scan blocks tips, predictions, and lucky number language anywhere in the output, outside an explicit disclaimer allowlist.
- **Semantic markup** — one `<main>` and one `<h1>` per page, every table captioned, every `<section>` a named region, every `aria-labelledby` resolving, ids unique.
- **Structured data** — every JSON-LD block must parse; the entity graph must resolve internally.
- **Canonical integrity** — one canonical per page, matching the sitemap exactly, one origin, no stray hosts.
- **Performance budget** — homepage ≤ 100 KB, inline CSS ≤ 10 KB, first party JS ≤ 2 KB per page.

A build that violates any of these does not ship. That is the point.

## How results get published

`scripts/auto-update.js` polls public sources and ingests only what it can confirm. Its safety rules were each added after a real incident:

1. **Dated history tables only** — never a source's "today" widget, which can roll to the next day early.
2. **Two source agreement** — a Patti is published only when independent sources concur.
3. **Time gate** — a bazi is never ingested before its scheduled declaration time has passed.
4. **Digit sum validation** — arithmetic is checked before anything is written.
5. **No silent correction** — a conflict with an already published result is reported for human review, never overwritten.
6. **Self healing window** — a multi day outage backfills automatically on the next run.

```bash
npm run build                 # full build + all assertions
npm run auto-update           # fetch, confirm, ingest, freeze, rebuild
npm run auto-update -- --dry-run
npm run add-result -- --date 2026-07-27 --bazi 3 --patti 378 --single 8
npm run freeze-day -- --date 2026-07-27
npm run serve                 # local preview of dist/
```

## Design constraints

Deliberate, and enforced:

- **Mobile first.** The audience is overwhelmingly on low end Android phones. The layout works at 360 px, the result table never scrolls horizontally, and layout shift is zero.
- **Light theme only.** Results get checked outdoors in daylight; maximum contrast is an accessibility requirement here, not a preference.
- **Bilingual.** English and Bengali (`lang="bn"`) throughout, because the audience is Bengali first.
- **Server rendered.** Results are real HTML text, never injected by JavaScript, so they are readable without scripts and indexable by machines.
- **No forms anywhere.** Contact is by email only.

## What this project is not

- **Not affiliated** with the operators of Kolkata Fatafat, any lottery body, or the Government of West Bengal. No official Kolkata FF website exists.
- **Not a source of guidance.** kolkataff.mobi does not publish tips, predictions, lucky numbers, or paid guidance of any kind — results and factual information only. Never pay anyone who claims to sell winning numbers; no one can predict a Kolkata FF result.
- **Not a place to play.** No betting is conducted, facilitated, or accepted here. The subject matter concerns adults 18 and over, and legality varies by Indian state.

Results are checked against multiple public sources before publication. The operators' declared result at the point of play always prevails over any website.
